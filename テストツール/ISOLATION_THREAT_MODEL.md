## 2. 信頼境界（Trust Boundaries）と脅威モデル（STRIDE分析）

アップロードされたコード、設定ファイル、PCAP、カスタムOSイメージはすべて **未信頼データ（Untrusted Data）** として扱う。

| 脅威カテゴリ | 想定される攻撃・障害シナリオ | 防御・緩和策（必須安全機構・常時ON） |
| :--- | :--- | :--- |
| **S / E: ゲストからホストへの脱出・権限昇格** | アップロードされた悪성スクリプトやカスタムイメージがホストOSのシェルやファイルシステムにアクセスする | ・未信頼コードをホストOS上で直接 `exec`/`eval` しない。<br>・VM/microVM 不在環境では実行テストを開始せず静的解析・ドライランにフォールバック。<br>・ホスト/ゲスト間の共有フォルダ（virtio-fs/9p等）を原則禁止。 |
| **I: 外部ネットワークへの意図しない通信・攻撃発信** | テスト中のパケットやボットシミュレーションが実インターネットやLANへ漏洩する | ・デフォルトで外部通信を完全禁止（`-nic none` または独立 Network Namespace 内で外部ルーティングなし）。<br>・ホストのファイアウォール/ルーティングを無断変更せず、隔離環境内部で閉じたインターフェースのみを使用。 |
| **D: リソース枯渇（Fork Bomb / OOM / Disk Full）** | $10^{16}$ パケット設定や暴走プロセスによりホストのRAM（残り565MiB）やディスク（残り1.4GiB）が枯渇する | ・プロセス単位の `RLIMIT_AS` / `RLIMIT_DATA` / `RLIMIT_NPROC` / `RLIMIT_CPU` / `RLIMIT_FSIZE` 強制。<br>・ログのリングバッファ＆最大ファイルサイズ制限。<br>・ホスト空きRAM `< 200 MiB` または空きDisk `< 500 MiB` で即時安全停止。 |
| **T / R: ログ消失・改ざん・停止偽装** | 障害発生時にログが欠落する、または停止表示のままバックグラウンドでプロセスが動き続ける | ・SHA-256ハッシュ連鎖監査ログ。<br>・停止時は `SIGTERM` → 猶予後 `SIGKILL` → PID/プロセスグループ/Namespace内残存プロセス `0` 確認まで「停止完了」とせず隔離も解除しない。 |
| **I: 配信・レポート経由の個人情報・秘密情報漏洩** | ホスト名 (`penguin`)、ユーザー名 (`harukiy1225`)、IPアドレス、ストリームキー等が画面やログに出る | ・`Privacy Protection & Redaction Engine` を常時有効化し、合成・出力前に全フィールドを検査。マスキング失敗時は Fail-Closed（配信・出力停止）。 |

## 3. コンテナ・Namespace と VM/microVM の明確な使い分け基準

「コンテナだけで完全な隔離が保証されると仮定しない」原則に基づき、実行モードを以下の3階層に厳格に分離する。

1. **Tier 1: ハードウェア仮想化隔離（KVM + QEMU / Firecracker microVM）**
   - **適用対象**: カスタムOSイメージの起動、未信頼バイナリやカーネルモジュール・XDPプログラムの動的ロード検証。
   - **必須条件**: `/dev/kvm` 利用可能、かつ署名検証済みハイパーバイザバイナリが存在すること。
   - **隔離設定**: `-nodefaults -no-user-config -nic none`（またはテスト専用隔離ソケット）、`-sandbox on`、シリアル出力最大サイズ制限（1MB）。
2. **Tier 2: カーネル名前空間＋リソース制限サンドボックス（Linux Namespaces + rlimit + Landlock/Seccomp）**
   - **適用対象**: 信頼済みのAegisLab/MK1Ai検証ハーネスコード（`airgap_ai_defender.py` 等）に対して、合成パケットデータ（バイト列）を入力して行うDPI・ネットワーク遮断シミュレーション。
   - **禁止事項**: ユーザーがアップロードした未信頼の実行ファイル・スクリプトを Tier 2 で直接実行してはならない。
3. **Tier 3: 純粋静的解析・ドライラン・数理モデル実行（No Execution Sandbox）**
   - **適用対象**: Tier 1 が利用できない環境での未信頼コード検査、および $1 \sim 10^{16}$ パケット・ボットの大規模数理シミュレーション。
   - **保証**: 外部プロセス起動やネットワークソケット生成を一切行わない。

## 4. 隔離違反検知・緊急停止・証拠保全プロトコル

隔離違反または重大障害を検知した場合、ホストのネットワーク設定を変更するような危険な副作用を避け、**隔離された検証環境内部の制御**によって以下の順序で安全停止を行う。

1. **Step 1: 通信・生成の即時凍結（Freeze）**
   - パケット生成ループ・送信トークンバケットを即時停止し、隔離環境内の仮想インターフェース（`veth` 等）またはソケットをクローズする。
2. **Step 2: 証拠スナップショットの保全（Evidence Preservation）**
   - 停止直前のカウンター値（目標・生成・開始・完了・ドロップ・エラー・未処理残数）、直近のリングバッファログ、違反検知理由、メモリ/CPU状態を不変ファイル（`halt-evidence-<timestamp>.json` + SHA-256）としてフラッシュする。
3. **Step 3: ゲスト/ワーカープロセスの強制終了と消滅確認（Kill & Verify）**
   - 対象プロセスグループまたはVMプロセスに `SIGTERM` を送り、2秒以内に終了しない場合は `SIGKILL` を送出する。
   - `/proc/<pid>` の消滅および対象 Namespace / cgroup 内の残存プロセス数が `0` であることを確認する。
4. **Step 4: 隔離解除ゲート（Isolation Release Gate）**
   - Step 3 で残存プロセス `0` が確認できた後にのみ、一時マウントや仮想インターフェースをクリーンアップし、状態を `HALTED_VERIFIED` として記録する。確認できない場合は隔離を維持したまま `HALT_INCOMPLETE_ALERT` を発報する。
