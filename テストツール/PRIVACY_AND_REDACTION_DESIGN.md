## 2. 検査・マスキング対象（14カテゴリ）と検出ルール

配信、録画、プレビュー、オーバーレイ、イベントログ、共有レポートのすべてにおいて、以下の情報を検査・マスキング対象とする。

| # | 検査対象カテゴリ | 検出方式（決定論的辞書 ＋ 構造化フィールド属性 ＋ 正規表現） | マスキング置換フォーマット |
| :--- | :--- | :--- | :--- |
| 1 | **IPv4アドレス** | 厳密オクテット境界検査（テスト用明示許可プレフィックス設定がない限り全IPv4を対象） | `[REDACTED_IPV4]` |
| 2 | **IPv6アドレス** | 標準・圧縮表記・IPv4射影アドレス (`::ffff:...`, `fe80::...` 等) | `[REDACTED_IPV6]` |
| 3 | **MACアドレス** | `([0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}` および Cisco 4桁ドット表記 | `[REDACTED_MAC]` |
| 4 | **Wi-Fi SSID / ネットワーク名** | `ssid`, `essid`, `bssid`, `wpa` キー属性およびネットワークインターフェース紐付け名 | `[REDACTED_SSID]` |
| 5 | **ユーザー名** | 実行環境の `os.getlogin()` / `pwd.getpwuid()` 実測値（例: `harukiy1225`）および `/home/<user>` | `[REDACTED_USER]` |
| 6 | **端末名・ホスト名** | `socket.gethostname()` / `uname().nodename` 実測値（例: `penguin`） | `[REDACTED_HOST]` |
| 7 | **メールアドレス** | RFC 5322 準拠パターン | `[REDACTED_EMAIL]` |
| 8 | **電話番号・住所** | 国際電話番号 (`+81-...`)、国内市外局番・携帯番号パターン、郵便番号 (`〒\d{3}-\d{4}`) | `[REDACTED_PHONE]` / `[REDACTED_ADDRESS]` |
| 9 | **APIキー・アクセストークン** | `Bearer ...`, `AIza...`, `ghp_...`, `sk-...`, `ya29....`、高エントロピーHex/Base64文字列 | `[REDACTED_TOKEN]` |

## 3. 多層マスキング方針と Fail-Closed 原則

1. **UI非表示（CSS）だけに頼らない合成前データ変換**:
   - フロントエンドへJSONを送信する前、およびCanvas/オーバーレイへ描画する前の**メモリ上のデータ構造自体**を `RedactionEngine` で書き換える。これにより、ブラウザの開発者ツールやDOM検査、映像エンコーダへの入力に平文が一切渡らないようにする。
2. **許可リスト（Allowlist）方式のソース管理**:
   - オーバーレイや配信に追加できるデータソースは、あらかじめスキーマが定義され検査パイプラインを通過した構造化ソース（カウンター、ステータスバッジ、サニタイズ済みイベントログ）のみを許可リストに登録する。
3. **アクセス権の分離**:
   - 内部デバッグ・監査用の生ログ（必要な場合）は `0600` 権限の隔離ディレクトリにのみ保存し、UI・配信・共有レポート生成エンジンからは直接読み取れないようにアクセス権とAPIを分離する。
4. **マスキング失敗時の Fail-Closed 動作**:
   - 万一、`RedactionEngine` 内で例外、タイムアウト、エンコーディングエラーが発生した場合、または未検査（`inspection_status != "VERIFIED_CLEAN"`）のソースが1つでも含まれる場合、**絶対にそのまま表示・公開を継続せず、即座に対象ソースを黒塗り非表示化し、録画・ライブ配信を強制停止（または開始ブロック）する**。
5. **画像内文字・未知識別子に関する誠実な限界明示**:
   - 画面キャプチャ等のビットマップ画像内の文字（OCR対象）や文脈依存の未知の個人情報を100%自動検出できるとは断言しない。そのため、画面キャプチャは初期OFFとし、有効化時には「画像内の文字は自動マスキング対象外となる場合があります。対象ウィンドウに機密情報が表示されていないことをプレビューで目視確認してください」という警告と手動チェックボックス確認を必須とする。

## 4. 配信前の安全チェック（Pre-Stream Safety Checklist）

ライブ配信または録画を開始する前、UI上に以下の7項目をリアルタイム表示し、すべてが安全基準を満たさない限り「配信開始」ボタンおよびバックエンドAPI `POST /api/v1/stream/start` をハードブロック（`BLOCKED`）する。

| チェック項目 | 安全基準（配信可能条件） | 異常時の挙動 |
| :--- | :--- | :--- |
| 1. 個人情報保護機能の状態 | `ACTIVE (常時有効・正常稼働中)` | 停止・異常時は **`配信不可 (BLOCKED)`** |
| 2. 秘密情報検査の状態 | 全アクティブソースの直近スキャンが `PASS (0 leaks)` | 漏えい検出またはエラー時は **`配信不可 (BLOCKED)`** |
| 3. 画面キャプチャの状態 | `OFF`（または対象ウィンドウ限定＋ユーザー目視確認済み） | 全画面キャプチャや未確認時は **`配信不可 (BLOCKED)`** |
| 4. マイクとデスクトップ音声の状態 | `OFF / Muted`（または明示的に承認・レベル確認済み） | 意図しない有効化がある場合は警告表示 |
| 5. 配信対象ソース一覧 | 許可リスト内の検査済みソースのみが列挙されていること | 未知ソース混入時は **`配信不可 (BLOCKED)`** |
| 6. 未検査ソースの有無 | **`0 件 (None)`** | 1件でも存在する場合は **`配信不可 (BLOCKED)`** |
| 7. 最終判定 | **`配信可能 (STREAMABLE)`** / **`配信不可 (BLOCKED)`** | 初期状態およびチェック未完了時は常に **`配信不可 (BLOCKED)`** |
