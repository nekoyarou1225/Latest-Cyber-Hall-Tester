## 3. シーン（7種）とオーバーレイソースの許可リスト制御

### 3.1 標準シーンテンプレート（7種）
1. **`SCENE_OVERVIEW`（テスト概要）**: テスト名、対象OS/バージョン、検証モード、全体ステータス。
2. **`SCENE_PACKETS`（パケット処理状況）**: 1〜1京の11カウンター（全桁表示＋単位表記）、進行率バー、経過/残り時間。
3. **`SCENE_BOTS`（仮想ボットの状態）**: 目標ボット数、モデル数、実プロセス/VM数、理論レート ($N \times 10\text{ Gbps}$) vs 実測レート比較。
4. **`SCENE_RESOURCES`（デバイスリソース状況）**: CPU、RAM、Disk、バッテリー%、電源状態、電力W（取得不可項目は「未対応/取得不可」と明示）。
5. **`SCENE_DPI`（DPI検証結果）**: 正常/悪性パケット判定数、誤検知/見逃し数、Fail-Closed 検証結果。
6. **`SCENE_XDP`（XDP/eBPF検証結果）**: Stage 1〜9 の到達マトリクス（未検証ステージの明示）。
7. **`SCENE_REPORT`（テスト完了レポート）**: 最終判定（`PASS`/`FAIL`/`INCONCLUSIVE`/`NOT TESTED`）と4区分サマリー。

### 3.2 オーバーレイ要素と安全規則
- **追加可能な要素**: テキスト、テスト名、シーン名、経過時間、パケット数、仮想ボット数、成功数、ドロップ数、エラー数、CPU/メモリ状態、バッテリー/電源状態、結果グラフ、警告バナー、マスキング済みイベント、透過背景。
- **制御属性**: 各ソースは `x, y, width, height, z_index, opacity, visible` を持ち、個別に表示/非表示を切り替え可能。
- **自動追加の禁止**: 未承認のソース（特に画面キャプチャや生の未検査ログ）を自動的にシーンや配信対象へ追加することは絶対にしない。

## 5. YouTube Live 等へのライブ配信連携設計（5段階分離）

### 5.1 配信方式の調査と対応方針
1. **方式A: RTMPS 入力方式（`rtmps://a.rtmp.youtube.com/live2` 等）**
   - YouTube Live 公式の暗号化インジェスト方式。ブラウザCanvas/音声ストリームをローカルバックエンド経由で `ffmpeg` 等のエンコーダプロセスに渡しRTMPS送出する。
   - **現環境の制約**: 現ホストには `ffmpeg` が未導入のため、現時点では「設定・プレビュー・安全チェック検証」までが動作可能であり、実RTMPS送出は **`ffmpeg` 導入承認後に有効化可能（現在は未検証・実行不可）** と正直に表示する。
2. **方式B: YouTube Data API / Live Streaming API v3 連携**
   - OAuth 2.0 による `liveBroadcasts` / `liveStreams` 制御（初期OFF、外部API連携承認時のみ）。
3. **方式C: 外部OBS Studio連携（ブラウザソースURL / 透過オーバーレイ出力）**
   - ローカルホスト (`127.0.0.1`) の専用エンドポイントで検査・マスキング済みの透過オーバーレイ画面を出力し、外部配信ソフトと連携する方式。

### 5.2 厳格に分離された5つの配信操作ステップ
以下の5操作は独立したAPIおよびUIボタンとして分離し、**ステップを飛び越えて配信開始することはできない**。

1. **`Step 1: 配信先設定 (Configure)`**: 配信サービス種別、RTMPS URL、ストリームキーを入力・暗号化保存する。**この時点では一切のネットワーク接続を行わない。**
2. **`Step 2: 認証・接続確認 (Verify Connection)`**: ユーザーの明示的操作によりエンドポイントの到達性・TLS証明書のみを確認し、即切断する（映像・音声は送らない）。
3. **`Step 3: プレビュー (Preview)`**: 合成画面と音声メーター、および **配信前安全チェック（11.3項）** の判定結果をローカル画面に表示する。外部送信は行わない。
4. **`Step 4: 配信開始 (Go Live)`**: 配信前安全チェックがすべて合格（`STREAMABLE`）であり、かつユーザーが確認ダイアログ（配信先・公開ソース一覧・個人情報保護状態を表示）で明示的に承認した場合にのみ送信を開始する。
5. **`Step 5: 配信停止 (Stop Live)`**: 即座にストリーム送出を停止し、ソケットおよびエンコーダプロセスの完全終了を確認する。再起動・回線瞬断時に自動再開することは禁止する。

### 5.3 ストリームキー・認証情報の保護
- UI入力欄は常時マスク（`••••••••••••`）とし、平文再表示ボタンを設けない。
- メモリ上でもラッパーオブジェクト (`SecretString`：`__repr__`/`__str__` が常に `"[REDACTED_SECRET]"` を返す) で保持し、ログ・例外トレース・レポート・配信URL表示への漏出を構造的に防止する。
- OSの資格情報ストア（Secret Service / Keyring、利用不可環境では `0600` 権限のAES-256-GCM暗号化ローカルボールト）に保存する。
