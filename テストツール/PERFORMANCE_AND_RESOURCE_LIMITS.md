## 2. 理論上の性能目標と実測値の厳格な分離

性能評価において、測定値を捏造したり、数式上の理論値を実測値として表示することは一切禁止する。すべての性能レポートおよび画面表示は以下の3階層を明確に分離して記録する。

| 指標区分 | 定義 | 例（1京ボット設定時） | 許容される表現 |
| :--- | :--- | :--- | :--- |
| **1. 理論モデル値 (`THEORETICAL_MODEL`)** | 数式 $R_{\mathrm{theoretical}} = N \times 10\text{ Gbps}$ 等に基づく純粋な数学上の設定値 | $10^{17}\text{ Gbps}$ ($10^{26}\text{ bit/s}$) | 「理論モデル上の計算値（実ネットワーク速度ではありません）」と明記 |
| **2. シミュレーション処理速度 (`SIMULATED_RATE`)** | メモリ上のバッチ・統計カウンターが1秒間に進める論理イベント数 | 例: 数理バッチ集計速度 | 「シミュレーションモデル上の論理集計速度（実通信なし）」と明記 |
| **3. 実測値 (` EMPIRICAL_MEASURED`)** | 隔離インターフェースや実CPU上で実際にバイト列を処理・送受信し、`monotonic_ns` で計測した値 | 例: 64B フレーム実処理 `xxx,xxx pps` (`0.xxx Gbps`) | 下記の **15必須環境・測定メタデータ** とともに「実測値」として記録 |

## 3. 実測時に必ず記録する15の必須メタデータ

実測ベンチマークを実行する際は、以下の15項目を自動で収集し、測定結果JSONに不可分な形でバンドルする。取得できない項目は推測せず `UNAVAILABLE` / `UNSUPPORTED` と記録する。

1. **使用CPU**: モデル名・コア数・スレッド数（現環境: `Intel(R) N100, 4 vCPUs`）
2. **メモリー容量**: 総RAM・開始時空きRAM・Swap有無（現環境: `Total 2.6 GiB, Swap 0 B`）
3. **GPUとVRAM**: デバイス有無（現環境: `UNSUPPORTED / No physical GPU counters in Crostini`）
4. **NIC**: テストに使用したインターフェース種別・MTU・ドライバ（例: `loopback` / `isolated veth pair, MTU 1500`）
5. **仮想化方式**: ホスト環境およびゲスト隔離方式（例: `Crostini KVM Host + Linux Namespace / QEMU`）
6. **OSとカーネル**: ディストリビューションと `uname -r`（現環境: `Debian 13 trixie / Linux 6.6.147-09648-g97ef00d8a343`）
7. **パケットサイズ**: テストフレーム長（例: `64 B`, `128 B`, `512 B`, `1500 B`）
8. **実測パケット処理数**: 実際に生成・処理完了した正確なパケット数（10進整数）
9. **実測送受信レート**: 経過時間あたりの実測 `pps` および `bps / Mbps / Gbps`
10. **CPU使用率**: 測定期間中の平均・ピークCPU使用率（%）
11. **メモリー使用量**: テストプロセスの開始時RSS、ピークRSS（`VmHWM` / `ru_maxrss`）、終了時RSS
12. **ドロップ数**: バッファ溢れまたはポリシーにより破棄された実測件数
13. **エラー数**: 例外・タイムアウト・破損等の実測件数
14. **測定時間**: `time.monotonic_ns()` による開始・終了・純粋経過時間（ナノ秒および秒）
15. **測定方法と測定環境の制約**: 測定経路（インメモリ関数呼び出し / ループバックソケット / 隔離veth）および環境制約（RAM上限・CPUスレッド制限・共有ホスト影響）の明記

## 4. 環境能力に応じた段階的検証（Stepped Verification）とハードリミット

現環境の能力を超える負荷をいきなり開始せず、以下の段階（Stage Gate）を順番にクリアした場合のみ次のステップへ進む設計とする。

| ステップ | パケット件数 / 規模 | 最大許容メモリ (RSS) | 最大許容時間 | 移行条件 |
| :---: | :--- | :---: | :---: | :--- |
| **Step 0: Preflight** | 0 件（環境・残容量チェック） | `< 50 MiB` | `2 秒` | 空きRAM $\ge 250\text{ MiB}$ かつ 空きDisk $\ge 600\text{ MiB}$ |
| **Step 1: Smoke** | $100$ 件 | `< 100 MiB` | `5 秒` | エラー0件、メモリリークなし、停止応答 $< 100\text{ ms}$ |
| **Step 2: Small** | $10,000$ 件 | `< 150 MiB` | `15 秒` | カウンター不変条件100%一致、RSS安定 |
| **Step 3: Medium** | $100,000 \sim 1,000,000$ 件 | `< 250 MiB` | `60 秒` | バッチストリーミング処理でRSSが一定（$O(1)$）であること |
| **Step 4: Large Sim** | $10^9 \sim 10^{16}$ 件（**数理モデル・統計バッチのみ**） | `< 250 MiB` | `60 秒` | 任意精度カウンターと統計モデルでメモリ増加ゼロを確認 |

※ `ISOLATED_REAL`（隔離環境での実パケット生成）モードでは、Step 4（$10^{16}$件）への実送信変換はハードコードで禁止し、ホスト能力に応じた安全上限（例：最大 $1,000,000$ 件または最大 $60$ 秒）で自動キャップする。
