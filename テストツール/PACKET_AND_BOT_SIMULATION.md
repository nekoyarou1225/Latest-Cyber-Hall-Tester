## 2. 1〜1京（$10^{16}$）の任意精度整数・丸め防止設計

### 2.1 IEEE 754 `Number` 型の禁止と10進文字列 + `BigInt` / Python `int` 規約
- **定数定義**:
  - 最小値: `1` (`"1"`)
  - 最大値（1京）: $10^{16} = 10,000,000,000,000,000$ (`"10000000000000000"`)
- **バックエンド（Python）**:
  - すべてのパケット数・ボット数・ビットレート計算は Python の任意精度整数 `int` および固定小数点 `decimal.Decimal`（精度50桁設定 `getcontext().prec = 50`）で処理する。`float` へのキャストは一切行わない。
- **API / JSON シリアライズ境界**:
  - JSON 上ではすべてのカウンター値を **厳密な10進数字文字列**（正規表現 `^[0-9]{1,27}$`）として伝送する。科学技術表記（`"1e+16"`）や浮動小数点は入力・出力ともにスキーマ違反として拒否する。
- **フロントエンド（JavaScript / TypeScript）**:
  - 受信した10進文字列は即座に `BigInt(str)` に変換して演算・比較を行い、表示時は完全な全桁表示（カンマ区切り `10,000,000,000,000,000`）と日本語単位併記（`1京0000兆0000億0000万0000`）の両方を提供する。省略表示のみにすることは禁止する。

### 2.2 独立管理する11のパケットカウンターと不変条件（Invariants）
以下の11項目を独立した状態変数として管理し、未処理分を完了済みに計上したり、目標数を完了数と混同したりしない。

| # | カウンター名 | 内部フィールド名 | 型（Backend / JSON / UI） | 定義・不変条件 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **目標パケット数** | `target_packets` | `int` / `str` / `BigInt` | ユーザー設定値 $T \in [1, 10^{16}]$ |
| 2 | **生成済みパケット数** | `generated_packets` | `int` / `str` / `BigInt` | シミュレータまたはジェネレータが生成した累計数 $G \le T$ |
| 3 | **処理開始数** | `started_packets` | `int` / `str` / `BigInt` | パイプラインへ投入開始した累計数 $S_{\mathrm{start}} \le G$ |
| 4 | **処理完了数** | `completed_packets` | `int` / `str` / `BigInt` | 処理が終端まで完了した累計数 $C = S_{\mathrm{ok}} + D + E \le S_{\mathrm{start}}$ |
| 5 | **成功数** | `succeeded_packets` | `int` / `str` / `BigInt` | 期待通り処理・通過または正常判定完了した数 $S_{\mathrm{ok}}$ |
| 6 | **ドロップ数** | `dropped_packets` | `int` / `str` / `BigInt` | ポリシー遮断・XDP/DPI DROP・バッファ溢れ等で破棄された数 $D$ |
| 7 | **エラー数** | `error_packets` | `int` / `str` / `BigInt` | 処理中に例外・破損・タイムアウトとなった数 $E$ |
| 8 | **残り数** | `remaining_packets` | `int` / `str` / `BigInt` | 厳密式: $R = T - C$（完了数 $C$ のみを差し引き、未完了分は減算しない） |
| 9 | **現在の処理速度** | `current_rate_pps` | `Decimal` / `str` | 直近ウィンドウの実績完了増分 $\Delta C / \Delta t$（モード別ラベル付き） |
| 10 | **経過時間** | `elapsed_ns` | `int` / `str` / `BigInt` | `time.monotonic_ns()` によるナノ秒精度の経過時間 |
| 11 | **推定残り時間** | `estimated_remaining_sec` | `str` (`"N/A"` or sec) | $\text{速度} > 0$ の場合 $R / \text{rate}$、速度 $0$ の場合は `"計測不能 (Infinite/Stalled)"` |

**厳密な不変条件（毎ステップ検証）**:
$$0 \le C = (S_{\mathrm{ok}} + D + E) \le S_{\mathrm{start}} \le G \le T \le 10^{16}$$
$$R = T - C$$
この不変条件が1つでも崩れた場合、`Isolation & Safety Controller` は「重大な整合性違反」として即座に安全停止する。

### 2.3 大量データ（$10^{16}$ 件）へのメモリ・ログ保護設計
- **一括メモリ保持の禁止**: 個別パケットオブジェクトを配列に保持することは行わず、固定サイズのリングバッファ（最大 1,024 件の標本フレーム）と $O(1)$ メモリ空間のストリーミング集計器（Welfordのオンライン分散・ヒストグラムバケット・任意精度カウンター）のみを使用する。
- **処理区分の明示**:
  - **個別実処理件数 (`individually_processed_packets`)**: 実際にバイト列を生成しDPI/パイプラインを通した件数。
  - **数理モデル計算件数 (`modeled_statistical_packets`)**: バッチ統計モデル上で計上した件数。
  - この2つをデータ構造上もUI上も**絶対に混同・合算して「実処理済み」と表示しない**。

## 3. 送信側仮想ボット（1〜1京）と 10Gbps 理論モデル設計

### 3.1 仮想ボット管理の10指標とプロセス爆発防止
$10^{16}$ 個のVM、プロセス、スレッド、ソケットを生成する設計はホストを即座にクラッシュさせるため厳禁とする。ボット群は **「階層的クラスタ状態ベクトル $(N_{\mathrm{active}}, N_{\mathrm{stopped}}, N_{\mathrm{uncreated}}, N_{\mathrm{error}})$」** として $O(1)$〜$O(K)$（$K \le 64$ グループ）のメモリ空間で数理表現し、実際に起動した主体数と厳密に分離して記録する。

| 管理指標 | 内部フィールド名 | 説明 |
| :--- | :--- | :--- |
| 1. 目標仮想ボット数 | `target_virtual_bots` | ユーザー設定値 $N \in [1, 10^{16}]$（10進文字列） |
| 2. モデル上のボット数 | `modeled_bots` | 数理シミュレーションモデル上に配置された論理ボット数 |
| 3. 実際に作成した論理エージェント数 | `actual_logical_agents` | メモリ上にインスタンス化した軽量オブジェクト数（上限 $\le 1,000$） |
| 4. 実際に起動したプロセス数 | `actual_spawned_processes` | OS上で実際に `fork`/`spawn` したプロセス数（現ホスト上限 $\le 4$） |
| 5. 実際に起動したVM数 | `actual_running_vms` | 実際に起動したゲストVM/サンドボックス数（現ホスト上限 $\le 1$） |
| 6. 状態別ボット数 | `state_counts` | `active`, `stopped`, `uncreated`, `error`（合計 $= N$） |
| 7. 各グループの状態 | `group_summaries` | リージョン/プロファイル別の集約バケット（最大64グループ） |
| 8. 合計パケット処理数 | `total_bot_packets` | 実処理件数とモデル件数を分離して保持 |
| 9. 理論上の送信レート | `theoretical_rate_bps` | 厳密式 $R_{\mathrm{theoretical}} = N \times 10\text{ Gbps}$ |
| 10. シミュレーション / 実測送信レート | `simulated_rate_bps` / `measured_rate_bps` | 下記5区分ルールに従い厳密に分離 |

### 3.2 10Gbps 理論モデルの計算式と5区分表示ルール
1ボットあたり最大 10 Gbps の理論モデルにおいて、合計理論レートは次式で定義される。

$$R_{\mathrm{theoretical}} = N \times 10\ \mathrm{Gbps} = N \times 10^{10}\ \mathrm{bit/s}$$

最大値 $N = 10^{16}$（1京）の場合：
- 仮想ボット数：$10^{16}$ (`"10000000000000000"`)
- 合計理論レート：$10^{17}\ \mathrm{Gbps}$ (`"100000000000000000 Gbps"`) $= 10^{26}\ \mathrm{bit/s}$ (`"100000000000000000000000000 bit/s"`)

UIおよびレポートでは、必ず以下の5つのステータスバッジを分離して同時表示する。

1. **`[理論値 / THEORETICAL]`**: 数式 $N \times 10\text{ Gbps}$ による純粋な数学的計算値（例: $10^{17}\text{ Gbps}$）。実ネットワークの速度ではない旨の注記を常時併記する。
2. **`[シミュレーション値 / SIMULATED]`**: 仮想シミュレーションモデル内で計算された論理スループット。
3. **`[実測値 / MEASURED]`**: 承認済みの隔離ネットワーク（`veth` 等）上で実際に送受信・計測された物理/カーネルスループット（例: `0.207 Gbps` 等）。実測を行っていない場合は絶対に数値を入れない。
4. **`[測定不可 / UNMEASURABLE]`**: 物理ハードウェア限界を超える領域、または対応センサー/NICが存在しない項目。
5. **`[未検証 / UNVERIFIED]`**: まだテストを実行していない、またはドライランのみの項目。

## 4. 3つの送信モードの厳密な分離

| モード名 | 初期状態 | 外部通信 | 実パケット生成 | 用途・制限事項 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 仮想シミュレーション (`VIRTUAL_SIM`)** | **OFF** | **完全禁止** | メモリ上の統計モデルまたは標本バッファのみ | $1 \sim 10^{16}$ ボット・パケットの数理挙動確認。実測値欄はすべて `未検証 (Not Measured)` と表示。 |
| **2. ドライラン (`DRY_RUN`)** | **OFF** | **完全禁止** | **なし（0件）** | 実行計画、必要リソース、上限、停止条件のみを算出し表示。通信成功の証拠としては扱わない。 |
| **3. 承認済み隔離環境での実測 (`ISOLATED_REAL`)** | **OFF** | **外部禁止**（隔離テストNW限定） | **上限付きで実施** | 許可された隔離インターフェース（例: `veth` `10.254.200.0/24`）のみ。宛先・プロトコル・最大pps・最大件数（例: $\le 10^6$ 件）・最大秒数（例: $\le 60$秒）を強制。$10^{16}$ 設定を実送信へ自動変換することはハードコードで禁止。 |
